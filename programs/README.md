# Demo programs

The list shown in the emulator is `catalog.json`. Programs by other authors are included with credit to their authors and sources; they are **not** covered by the project license. Each entry names its author (when known) and origin. Programs by the project's author are marked GPL-3.0-or-later.

Nostalcomp ([nostalcomp.cz](https://www.nostalcomp.cz/)) preserved and shared much of the PMI-80 software. Its article on games for the PMI-80, cited below, is no longer on the redesigned site; it survives in the Internet Archive: [Hry na PMI-80](https://web.archive.org/web/20190525100848/http://www.nostalcomp.cz/pmi_hry.php).

## Layout, Intel HEX files and byte lists

One folder per program, named after the program (`cosmos/`, `bagels/` …); in it one file per board, named `<program>-<board>` (`-pmi80`, `-savia`, `-stone1`). The catalogue ids carry the same board suffix, and the catalogue's `file` paths point into the program's folder.

Beside every source (`.asm`) and every binary image (`.bin`) there are two listings of the same name, made by `node tools/make-listings.mjs` (`--check` only compares) and kept up to date by a test: an **Intel HEX file** (`<name>.hex`) and a **list of bytes** (`<name>-bytes.txt`: 16 bytes to a line, each line starting with its address and a colon, as one types them into a monitor). Both hold exactly the bytes the emulator loads, so a program can be handed out without the emulator, typed into a real board through its monitor or loaded by any HEX-aware tool. The addresses are those of the board's RAM (PMI-80 from 1C00, Savia-84 and Stone 1 from 1800, or as the program's header says); the header of each source names the start address. The files are text with LF line endings (`.gitattributes` keeps them as they are, so a checkout does not change them). They carry the same licence and origin as their source: a listing of a program by another author is that author's work, not the project's. Programs that live inside a ROM (format `rom`) have no files, and files that are already Intel HEX (AION Buzzer 80, the original COSMOS) have no extra ones.

## Sources in the builds

The repository keeps every program as written: for most of them an assembler source (`format: 'asm'` in the catalogue), with its comments. **The builds (`dist/web`, the offline HTML, the EXE) carry only the assembled programs** (the maintainer's decision, 2026-10-29): for an `asm` entry `tools/build.mjs` (through `tools/program-assets.mjs`) embeds the Intel HEX beside the source, marks the embedded entry `format: 'ihex'`, `sourceFormat: 'asm'`, and refuses to build if that HEX does not match its source. The catalogue itself still says `asm`; it describes the repository, not the build.

**Why the sources were embedded until then.** It was the simplest way: the build put every catalogue file into the page as it was, and the app assembled the source each time a program was started. That kept one source of truth, guaranteed that what runs is what the source says, kept the offline HTML complete on its own (the repository is not public yet), and left the door open for the planned development environment.

**Why not any more.** Nothing in the app shows the sources; they were only assembled. With the ported games they grew to 471 kB of the 834 kB offline HTML (base64 of commented sources, one per board), and each new game added about 60 kB. The HEX files already exist and are checked against the sources by a test and by the build, so the guarantee stays.

**What they may be good for later, and how to get them back.** An in-app view of a game's source (the PMI-80 was a teaching computer, and reading how a game is written fits it), opening a game as an example in the planned editor and assembler (`docs/TODO.md`, "Assembler and development environment"), or a single file that carries everything when the HTML is handed out. `node tools/build.mjs --with-sources` already adds every `asm` source, gzipped and base64-encoded, as the entry's `source` field (about a quarter of the plain size); `programSource(entry)` in `src/machine/programs.js` unpacks it in the browser (`DecompressionStream`), and `tests/program-assets.test.mjs` keeps that path working. To bring the sources back, make the switch the default (or have the web version fetch the files on demand) when that feature is built; nothing else needs to change.

### Games from other single-board trainers

Games of other trainers with a hex keypad and seven-segment digits (KIM-1, TK-80, MK14, Acorn System 1 …), written anew for the 8080 by this project (GPL-3.0-or-later) after the rules of the originals, whose authors are named here and in each game's notes; no original code is copied. Each game has its own folder, one source per board, its own test `tests/game-<id>.test.mjs` and its own version in its header and in the catalogue. On the PMI-80 they beep through K3 with segment g dark for the beep; the Savia-84 and the Stone 1 versions are silent.

To remove a game: delete its entries from `catalog.json`, its rows below, its folder and its test (or revert the commit that added it). Nothing else depends on it.
